# 工作区：目录、生命周期、运行流程

> 说人话版本。想了解为什么这么设计，看 [workspace.md](workspace.md) 和 [workspace-cli-credentials.md](workspace-cli-credentials.md)。
> 核对时间：2026-11-22 下午。库里数字是当时查的，会变。
>
> 四个模式（local 没配目录 / local 配了目录 / docker / kubernetes）**每节末尾都有「各模式对照」表**；
> 一屏看完的版本在第 15 节。

## 一句话

工作区 = **一个目录 + 一套执行方式**。目录没有两种，就是**宿主机上的一个目录**：

- 没配目录 → 用默认目录：`~/.billy/workspaces/<工作区编号>`；
- 配了目录 → 就用你给的那个路径（必须已经存在）。

配没配只影响一件事：**初始化跑不跑**。没配，平台会往里放技能、凭据、标记；配了，平台一个字节都不写，因为那是你自己的目录。

>
> 本文记录的是**现在的行为**；已定的调整方向见
> [workspace-env-contract.md](workspace-env-contract.md) §9.1（Host 改为搬技能、沙箱开关改布尔、Windows 进支持矩阵）。

## 1. 三条共用规则

1. **会话只在「默认工作区」里跑**：会话表上有 `workspace_id`，建会话时绑的是默认工作区。列表里其它工作区，聊天用不到。
2. **能力调用先找目录**：`bash` 和 7 个文件能力调用时只带会话 id，执行面按会话查工作区（30 秒缓存，子会话沿根会话）。
3. **bash 先过凭据检查**：命令里出现 `gh` / `lark` / `mysql` / `redis-cli` / `tccli` 而本地清单没有对应凭据 → 直接拒绝，不执行。

## 2. 每种模式的生命周期

### 2.1 local · 没配目录（默认）

| 阶段 | 发生什么 | 实际动作 |
| --- | --- | --- |
| 第一次调用 | 建工作区、起环境 | `mkdir -p ~/.billy/workspaces/<id>` |
| 初始化 | 装包（清单空则跳过）→ 放技能 → 落凭据 → 写标记 | 都在沙箱里跑 shell 命令 |
| 技能 | 写进 `.agents/<key>/`，删掉不再可见的 | 见第 4 节 |
| 凭据 | 写进你家目录，登记清单 | 见第 5 节 |
| 跑命令 | 进沙箱执行 | `sandbox-exec` / `bwrap` 包一层 `sh -c`，只能写工作区和几个缓存目录 |
| 读写文件 | 直接读磁盘 | Node 文件操作，路径必须在工作区内 |
| 空闲 2 小时 | 回收 | 只丢掉内存里的记录，**目录还在** |
| 删除工作区 | 删记录 | **不删目录**（想清就自己 `rm -rf`） |
| 再次调用 | 重新 ensure | 目录还在，初始化靠 `.billy/` 标记跳过重装 |

### 2.2 local · 配了目录

| 阶段 | 发生什么 | 实际动作 |
| --- | --- | --- |
| 第一次调用 | 先检查 | 必须是已存在目录；在允许的根下面；不把 `.ssh` 这类凭据目录包进来；沙箱必须是开着的 |
| 起环境 | 不建目录 | 目录必须已存在，不替你创建 |
| 技能 | **照写**：物化到 `.agents/<技能名>/`（2026-11-22 起，两种目录形态一致）；收敛时只删带 `.billy-skill` 标记的目录 | 写入用 Node fs 直写，不依赖 shell |
| 凭据 | **不写、不登记**（声明 `writeHome: false`） | 所以执行前的凭据检查读不到清单 → 放行（见第 16 节第 3 条） |
| 跑命令 | 同 2.1 | 沙箱，但工作区根 = 你给的路径 |
| 读写文件 | 同 2.1 | 路径必须在那个目录里 |
| 空闲 2 小时 | 回收 | 丢内存记录，目录不动 |
| 删除工作区 | 删记录 | 目录绝对不动 |

### 2.3 docker

| 阶段 | 发生什么 | 实际动作 |
| --- | --- | --- |
| 第一次调用 | 建容器并启动 | `docker create` + `start`：`/workspace` 是内存盘、能力全丢、禁止提权、限内存 / CPU / 进程数 |
| 镜像变了 | 重建 | 发现容器用的镜像和配置不一致 → 删了重建 |
| 初始化 | 同上四件事 | 在容器里跑 |
| 技能 | 写进容器内 `/workspace/.agents/` | 容器删了技能也一起没，重建时重跑初始化 |
| 凭据 | 写进**容器内**的 HOME | 宿主机上看不到 |
| 跑命令 | 进容器执行 | `docker exec sh -c`，工作目录 `/workspace/<子路径>` |
| 读写文件 | 翻译成容器命令 | 列目录 `ls`、树 `find`、读 `cat`、写 `tmp` + `mv`、删 `rm -rf` |
| 空闲 2 小时 | 停容器 | `docker rm -f`，**数据一起没** |
| 删除工作区 | 同空闲回收 | 容器没了就是没了 |

### 2.4 kubernetes

| 阶段 | 发生什么 | 实际动作 |
| --- | --- | --- |
| 第一次调用 | 建 Pod 并等就绪 | `kubectl apply` 一个 Pod（`/workspace` 是空目录卷、不挂服务账号、能力全丢）→ 轮询最多 60 秒等 Running |
| 初始化 | 同上四件事 | `kubectl exec` 进 Pod 跑 |
| 技能 / 凭据 | 写进 Pod 里 | 和 docker 一样，Pod 删了就没 |
| 跑命令 | 进 Pod 执行 | `kubectl exec -- sh -c 'cd <路径> && <命令>'` |
| 读写文件 | 同 docker | 每条文件操作一次 exec |
| 空闲 2 小时 | 删 Pod | 数据一起没 |
| 多副本 | 支持 | 锁和"最后使用时间"放 Redis，任意副本都能处理任意工作区 |

### 2.5 microvm

只有枚举值，选中直接报「未实现」。没有生命周期。

## 3. 运行流程（一次调用怎么走）

### 3.1 跑一条命令

```
模型调 bash
  → 找到会话绑定的工作区
  → 凭据检查（命中 gh/lark/... 但没凭据 → 拒绝）
  → 工作区在内存里没有记录？
      是 → 建记录（并发只建一次）→ 起环境 → 初始化（配了目录就跳过）
      否 → 直接用
  → 同一工作区的命令排队（一次只跑一条）
  → 分开执行：
      local  → 沙箱里跑
      容器   → 进容器跑
  → 返回退出码、stdout、stderr、耗时、是否被截断
```

### 3.2 读一个文件

```
模型调 file-read
  → 找会话绑定的工作区 → 确保环境在
  → local：直接读磁盘（先判路径在不在工作区内）
    容器：进容器 cat
  → 超过 512KB 不允许在线预览，只能下载（上限 8MB）
```

### 3.3 写一个文件

```
模型调 file-write
  → 找会话绑定的工作区 → 确保环境在
  → 同一路径的写排队（不同路径互不影响，读不排队）
  → 先写同目录临时文件，再改名覆盖（这样别人不会读到半截）
```

### 3.4 第一次调用和之后的差别

| | 第一次 | 之后 |
| --- | --- | --- |
| 建目录 / 起容器 | 做 | 不做（除非被回收了） |
| 初始化 | 做（配了目录则跳过） | 不做（靠 `.billy/` 标记） |
| 技能与凭据 | 写 | 不重写（凭据每次启动仍会重新落地） |
| 凭据失败补偿 | 每 5 秒重试一次 | 重试到成功为止 |

### 3.5 各模式对照（同一次调用，落在哪）

| | local 没配目录 | local 配了目录 | docker | kubernetes |
| --- | --- | --- | --- | --- |
| 第一次调用做什么 | 建目录 + 初始化 + 起沙箱 | 只校验目录 | 建容器 + 初始化 | 建 Pod + 等就绪 + 初始化 |
| `bash` 落在哪 | 宿主沙箱里 | 宿主沙箱里 | 容器 `sh -c` | Pod `sh -c` |
| 读文件落在哪 | 直接读磁盘 | 直接读磁盘 | 容器 `cat` | 容器 `cat` |
| 写文件怎么保证不被读半截 | 同目录临时文件 + 改名 | 同左 | 同左（`mv -f`） | 同左 |
| 环境不在了怎么办 | 重新建记录（目录还在） | 重新校验 | 重新起容器 | 重新起 Pod |

## 4. 技能操作（谁进来、怎么进来、怎么删）

### 4.1 哪些技能会被放进来

| 技能类型 | 谁能看到 |
| --- | --- |
| 内置（`builtin`） | 所有人 |
| 平台导入 / 在线创建 | 默认看不到，要显式授权（授给所有人，或授给某个账号） |
| 个人技能 | 只有作者自己 |
| 超管 | 全部平台技能 |
| 同名 | 个人技能覆盖平台技能 |

按当前库：启用技能 7 个，默认管理员是超管 → 全部 7 个（约 538 个文件）会进工作区；普通管理员只有「内置 + 已授权」2 个。

### 4.2 放进去的过程

```
初始化第②步
  → 查这个工作区的主人的可见技能
  → 逐个技能写文件：.agents/<技能名>/<文件>
      先写 SKILL.md（模型真正要读的正文）
      一个文件失败不影响其它文件（记 partial）
      内容按 48KB 分片写（一条命令传太长会失败）
  → 全部成功才写幂等标记 .billy/setup/<清单>@<hash>.done
      hash 覆盖"装了哪些东西 + 技能内容"
      → 技能内容一变，hash 就变，下次会重新物化
      → 有技能没写全，就不写标记（避免一次失败被永久固化）
```

### 4.3 删掉的过程（撤销授权后）

```
后台改了技能授权 / 删了技能
  → main 通知执行面"同步一下技能"
  → 列出工作区 .agents/ 下的目录
  → 凡是不在可见列表里的（且名字合法）→ rm -rf .agents/<技能名>
```

**为什么必须删**：不删的话，被撤销授权的人还能用文件工具读到技能正文，授权就形同虚设。

### 4.4 模型怎么用技能

就是读工作区里的 `.agents/<技能名>/SKILL.md` 和配套文件，没有第二条加载通道。所以「技能进没进来」等价于「文件在不在」。

### 4.5 各模式差别

| | local 没配目录 | local 配了目录 | docker | kubernetes |
| --- | --- | --- | --- | --- |
| 初始化时写入 | 写 | 不写 | 写 | 写 |
| 撤销授权时删除 | 删 | 不删 | 删 | 删 |
| 环境重建后 | 目录里还在，靠标记跳过 | 本来就没有 | 没了，重跑初始化 | 没了，重跑初始化 |

## 5. 凭据操作（怎么落地、怎么检查、失败怎么办）

### 5.1 落地过程

```
初始化第③步（每次启动都会重做，比装包便宜）
  → 执行面按"工作区主人"查有哪些可用凭据（执行面自己不存密钥）
  → 调 main 的内部接口，用凭据名换回明文
  → 按模板把明文渲染成文件或环境变量
      文件：600 权限；模板字段缺失就整条失败，不写半截
      环境变量：后续每条命令都带上
  → 写清单 .billy/credentials.json（只有 provider / 名字 / 到期时间，没有明文）
  → 写 .billy/setup.json 记版本号
```

现在三个模板写到哪：GitHub → `~/.config/gh/hosts.yml`；Lark → `~/.lark-cli/config.json`；MySQL → `~/.my.cnf`。

### 5.2 执行前检查

```
模型调 bash
  → 把命令行按 ; && || | 换行 拆段
  → 每段跳过 sudo / env / 变量赋值，看第一条命令名
  → 命中 gh / lark / lark-cli / mysql / redis-cli / tccli 其中之一
      清单里没有这个 provider 的可用凭据 → 拒绝，不执行
      有 → 放行
  → 豁免：`auth login` 这类配置命令、以及 --help / --version 探测
```

拒绝分两种：**确实没有 / 已过期**（让模型想办法），**凭据正在自动补偿**（提示几秒后重试，别换路）。

### 5.3 失败与补偿

| 情况 | 处理 |
| --- | --- |
| 找 main 换明文这一步整体失败 | 标「凭据没就绪」，每 5 秒重试一次，成功就停 |
| 某一条凭据写文件失败 | 只记一笔失败，**不重试**（这是现在的坑，见第 16 节第 1 条） |
| 清单文件读不出来 / 读到半截 | 不缓存，拒绝之前再读一次磁盘 |
| 容器里 `cat` 返回非 0 | 当读取失败，不能当成"空清单" |

### 5.4 后台改了凭据之后

```
后台保存 / 吊销 / 刷新凭据
  → main 通知执行面"凭据变了"
  → 执行面只在工作区**正在运行**时重新落地（不主动拉起）
  → 重新写文件 + 更新清单；如果这次也带了技能变更，顺带做技能收敛
```

### 5.5 各模式差别

| | local 没配目录 | local 配了目录 | docker | kubernetes |
| --- | --- | --- | --- | --- |
| 文件写到哪 | 你电脑的 HOME | **不写** | 容器内 HOME | Pod 内 HOME |
| 清单 `.billy/credentials.json` | 写 | **不写** | 写 | 写 |
| 执行前检查 | 按清单拦 | 读不到清单 → 放行 | 按清单拦 | 按清单拦 |
| 失败补偿 | 有 | 无（没这一步） | 有 | 有 |

## 6. 安装清单（除了技能和凭据，初始化还会装什么）

清单是**一张表**（`ai_workspace_setups`），三块内容：

| 块 | 内容 | 现状 |
| --- | --- | --- |
| `packages` | 装哪些 CLI：`[{ 管理器, 包, 验证命令 }]` | 库里 0 条 → 空跑 |
| `files` | 写哪些非凭据配置文件：`[{ 路径, 内容 }]` | 空 |
| `env` | 设哪些非敏感环境变量 | 空 |

- **归属**：每个账号一份 `default` 清单；工作区可以指定别的清单（`setup_id`），还能追加只对自己生效的项（`setup_extra`）。
- **为什么要管**：「装好了的 CLI」不算资产，挂了就没了；「要装哪些、什么版本」才算，重建时按它重放。
- **只能后台编辑**：清单在模型执行前跑，等于「可持久化的代码执行」，所以模型只能建议，不能改。
- **支持的管理器**：`npm` / `pnpm`（全局装）、`apt`、`pip`、`uv`。
- **装法**：每项先跑验证命令，过了就记 `skipped`（命中缓存）；没过才装，装完再验一次，还不过记 `failed`。
- **预算**：验证 20 秒、单个安装 3 分钟、整体 5 分钟；超了记 `timeout`。
- **四种结果都不阻断**：`installed` / `skipped` / `failed` / `timeout` 只进报告，工作区照样能用。
- **配置文件**写失败只记日志（当可选配置处理）。
- **谁在维护**：目前**没有任何接口或页面**能编辑清单（main / admin 都没有引用这张表），只能手工插库 —— 所以它一直是空的。

### 6.1 各模式对照

| | local 没配目录 | local 配了目录 | docker | kubernetes |
| --- | --- | --- | --- | --- |
| 装包 | 跑，但沙箱写不了全局安装目录 → 多半记 `failed` | 跳过 | 容器里可装 | Pod 里可装 |
| 配置文件 | 写进工作区 | 跳过 | 写进容器 | 写进 Pod |
| 环境变量 | 注入后续每条命令 | 无（初始化整段跳过） | 注入 | 注入 |
| 幂等标记 | 在目录里，重启仍有效 | 无 | 在容器里，容器删了就重跑 | 同 docker |
| 失败影响 | 都不阻断，只进报告 | — | 同 | 同 |

## 7. 后台能做什么（页面和接口）

页面 `/main/ai/workspaces`：

| 能做 | 说明 |
| --- | --- |
| 新建 | 选「本地」或「容器」；本地可填目录（留空用默认目录） |
| 启动 / 停止 | 只写「期望状态」，实际动作交给执行面 |
| 删除 | 默认工作区不能删；删的是记录，local 的目录不动 |
| 看文件 | 树状列表 + 文本预览 + 下载；工作区没在跑时直接报错，不会偷偷拉起 |

- 卡片上的「运行中 / 已停止」是**实际状态**：每次列表都去问执行面，数据库里只有「期望状态」。
- 超管能看到别人的工作区，卡片上标了归属人。
- 控制面接口（main，全 POST）：`list` / `create` / `update` / `remove` / `start` / `stop` / `files` / `file/read` / `file/download`。
- 执行面接口（workspace-service）：`ensure` / `stop` / `destroy` / `status` / `sync` / `exec` / `fs`，另有 `/invoke`、`/tasks/get`、`/tasks/cancel` 给网关回调用。

### 7.1 各模式对照

| | local 没配目录 | local 配了目录 | docker | kubernetes |
| --- | --- | --- | --- | --- |
| 启动做了什么 | 建目录 + 初始化 | 校验目录，不做别的 | 建容器（镜像不对先重建） | 建 Pod，等 Running（最多 60 秒） |
| 启动失败的典型原因 | 目录建不出来 | 目录不在允许根内 / 不存在 / 没开沙箱 | 镜像不存在、docker 连不上 | 集群不可达、Pod 起不来 |
| 停止 | 丢内存记录，目录留着 | 同左 | 删容器，数据没了 | 删 Pod，数据没了 |
| 删除 | 删记录，目录留着 | 删记录，目录不动 | 删记录 + 删容器 | 删记录 + 删 Pod |
| 卡片状态从哪来 | 内存里有记录就算运行中 | 同左 | 去问容器在不在 | 去问 Pod 在不在 |

## 8. 模型能调用什么（能力面）

登记在能力网关的服务叫 `workspace`，现在 **11 个能力**（旧文档写 8 个是当时只有 bash + 7 个文件能力）：

| 能力 | 形态 | 说明 |
| --- | --- | --- |
| `bash` | 任务型 | 先受理再轮询，等 45 秒没跑完就交给任务接口；单条最长 30 分钟，工具超时 300 秒 |
| `file-list` / `read-file` / `write-file` / `append-file` / `replace-file` / `file-search` / `workspace-files` | 直接返回 | 7 个工作区文件能力（`read-file` 默认 200 行 / 16KB 分页） |
| `credential-candidates` / `credential-import` / `credential-save` | 直接返回 | 从工作区里发现 / 导入 / 保存凭据 |

调用链：模型 → 工具 → 能力网关 → workspace-service → 工作区。返回里 `bash` 带运行时标记（`sandbox` / `container`）、退出码、耗时、是否截断；文件能力失败带原因（`unsafe-path` / `exec-failed`）。

### 8.1 各模式对照

| | local 没配目录 | local 配了目录 | docker | kubernetes |
| --- | --- | --- | --- | --- |
| `bash` 在哪跑 | 宿主沙箱 | 宿主沙箱 | 容器里 | Pod 里 |

## 9. 并发与多副本

单进程内：

- 同一个工作区并发 ensure 只做一次（单飞表 + 生命周期锁）；
- 同一个工作区的命令**排队**执行，一次一条；
- 文件写按「工作区 + 路径」排队，读不排队；
- 写文件先写同目录临时文件再改名，读的人不会读到半截。

多副本：

| 后端 | 多副本 | 条件 |
| --- | --- | --- |
| local | 不支持 | 目录在 Pod 本地盘，启动就拒绝 |
| docker | 仅同宿主 | 所有副本共享同一个 docker daemon（要显式开关）+ Redis |
| kubernetes | 支持 | 锁与「最后使用时间」放 Redis |

- 回收时同时拿「生命周期锁」和「命令锁」，拿不到就跳过（有人在用）。
- 容器名是固定的 `billy-ws-<工作区编号>`，所以任意副本都能探活 / 删除。

### 9.1 各模式对照（锁放哪）

| | local 没配目录 | local 配了目录 | docker | kubernetes |
| --- | --- | --- | --- | --- |
| 单飞（并发 ensure 只做一次） | 进程内 | 进程内 | 进程内；多副本抽 Redis | 进程内；多副本抽 Redis |
| 命令排队 | 进程内 | 进程内 | 进程内；多副本靠 Redis 命令锁 | 同 docker |
| 文件写排队 | 进程内按路径 | 同左 | 同左 | 同左 |
| 多副本 | 不支持 | 不支持 | 仅同宿主 + Redis | 支持 |

## 10. 会话怎么绑到工作区

- 建会话时绑**默认工作区**；没有就懒创建一条。
- 一个账号一条默认工作区就够；列表里其它工作区**聊天用不到**（没有选择器）。
- 子会话沿根会话的工作区。
- 绑不到时报「会话还没有绑定工作区」。

### 10.1 各模式对照（会话绑到哪种工作区，聊天里就是什么）

| 会话绑到 | 聊天里 `bash` / 文件落在哪 | 有技能和凭据吗 | 停一次会怎样 |
| --- | --- | --- | --- |
| local 没配目录 | `~/.billy/workspaces/<id>` | 有 | 记录没了但目录在，下次接着用 |
| local 配了目录 | 你给的那个目录 | **都没有** | 目录原样不动 |
| docker | 容器内 `/workspace` | 有 | 容器删了，内容全没，下次重建重装 |
| kubernetes | Pod 内 `/workspace` | 有 | Pod 删了，内容全没，下次重建重装 |

## 11. 安全边界（能读写什么、能写到哪）

三层防线：

| 层 | 谁管 | 拦截什么 |
| --- | --- | --- |
| 容器 / Pod | docker / k8s | 拿不到宿主文件系统、控制不了 docker daemon、限资源 |
| 宿主机沙箱 | local 后端 | 只能写工作区和几个缓存目录，凭据目录禁读 |
| 目录闸口 | 配了目录时 | 允许根、不能覆盖凭据目录、必须开沙箱 |

容器加固清单：能力全丢、禁止提权、不挂 docker.sock、不挂宿主目录、`/workspace` 是内存盘、限内存 / CPU / 进程数、网络默认可出网（`none` 就断网）、seccomp 默认策略；**不设只读根**（初始化要全局装包，只读根会直接失败）。

沙箱（local 后端）：默认强制，沙箱不可用就**拒绝执行**，不退回裸跑；macOS 用 `sandbox-exec`、Linux 用 `bwrap`；能读全盘（除凭据目录），只允许写工作区和缓存；网络默认断。

禁读清单：`~/.ssh`、`~/.aws`、`~/.gnupg`、`~/.kube`、`~/.docker`、`~/.netrc`、`~/.pgpass`、`~/.git-credentials`、`~/.npmrc`、`~/.config/gh`、`~/.billy/lark-cli`。

云端多租户**不能用 docker 后端**：挂 `docker.sock` 等于把宿主 daemon 交出去。

### 11.1 各模式对照

| | local 没配目录 | local 配了目录 | docker | kubernetes |
| --- | --- | --- | --- | --- |
| 隔离边界 | 宿主沙箱 | 宿主沙箱 + 目录闸口 | 容器 | Pod |
| 能读宿主其它文件 | 能（除凭据目录） | 能（除凭据目录） | 不能 | 不能 |
| 工作区外还能写哪 | 几个缓存目录 | 同左 | 容器内任意位置 | Pod 内任意位置 |
| 命令能联网吗 | 默认断 | 默认断 | 默认可出网（可配断网） | 同 docker |
| 多租户能用吗 | 不能 | 不能 | 不能（会暴露宿主 docker） | 能 |

## 16. 现在的问题（按严重程度）

1. **凭据"登记成功但没写成"**：代码先登记有凭据、再写文件，写失败只记一笔失败。结果平台以为你有凭据、放行命令，命令跑起来说没登录。开着沙箱时必现（`~/.config/gh` 这类路径写不进去）。
2. **只读工作区的初始化必然失败**：技能、标记都写不进沙箱，只在报告里留一堆失败。
3. **配了目录时完全没有凭据清单**：检查读不到清单就放行，命令跑起来才发现没登录。和"没凭据"应该区分开。
4. **"删除工作区"不删数据（local）**：名字和行为不一致，容易让人误以为清理干净了。
5. ~~**默认目录不一致**~~：已统一为 `~/.billy/workspaces`（2026-11-22）。
6. **技能同步靠目录名匹配**：`.agents/` 下只要名字合法、又不在可见列表里，就会被 `rm -rf`。以后要是有别的东西也放 `.agents/`，会被当垃圾清掉。
7. **初始化清单没有编辑入口**：表存在、执行面会读，但后台没有页面也没有接口，只能手工插库；所以「装包 / 配置文件 / 环境变量」这三块永远是空的。
