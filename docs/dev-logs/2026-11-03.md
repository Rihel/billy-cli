# 2026-11-03

**会话页卡死：前端按 part 类型增量归约（后端零改动）**：

①诊断：会话 `vske8ur0le74hwsfii0s`（1 轮 4 路并行子助手）单条消息的 parts 被撑到约 3.5 万条
（Redis 输出记录 `LLEN=20000` 已顶 cap，其中 `data-sub-agent-delta` 12,868 条、平均 3.47B/块），
而渲染层每帧要扫 4–6 遍 parts、生成同样长度的 children，主线程长期超 100%。

②修法：
- `chat-transport.ts`：继承 `DefaultChatTransport`，在 `processResponseStream` 后给
  `data-sub-agent-delta` 打 `transient: true`（SDK 正式通道：只走 `onData`、不落 part），续传同一条路；
- `chat-session.ts`：`ChatSessionStore` 按 type 增量归约（text/reasoning 同下标覆盖、工具按
  `toolCallId` upsert、子助手增量折叠进聚合正文、事件有主并入/无主独立、计划与用量单列），
  `onData` 的实时数据 100ms 合并通知，`data-run` 清空上一轮；
- `message-row.tsx` → `ChatMessage`：只吃归约好的单元并 `memo`；子助手卡各自订阅
  `useLiveSubAgent(runId)`，实时增量不带动整行/整个列表；
- 右栏改订阅 store，历史子助手过程用 `toMessageState` 走同一套归约。

③方案与证据：`docs/design/ai-chat-state.md`。验证：admin typecheck / 176 用例 / `check:ui` 全绿；
界面交人工验（多子助手任务跑一轮：消息流流畅、子助手卡边跑边长、刷新后历史与实时同形）。

**计时口径统一为"整秒"**：工具条原来 `setInterval(500)` 采样、再按一位小数显示（`1.2s`），
数字按 0.5 一跳（0ms → 500ms → 1s → 1.5s），收尾还比真实耗时少一截；思考计时运行中只有
"思考中…"、结束才 `ceil` 出秒数。新增 `use-elapsed.ts`（250ms 采样 + 整秒状态，跨秒才翻字、
值不变时 React 直接 bail out），工具条运行中显示整数秒、有审计耗时时仍显示一位小数；
思考运行中显示"思考中… Ns"，历史秒数改 `ceil` 与实时收尾同口径。typecheck / 180 用例 / check:ui 全绿。

**修会话页 SSR 崩溃（Provider 位置错）**：`ChatSessionProvider` 原先建在 `ChatConversation` 内部并作为它
`return` 的一部分，组件体里的 `useContext` 因此永远读到 null —— 报「会话 store 缺失」、Next 退化为整页
客户端渲染，`min-h-screen` 的加载骨架与真实内容叠加，文档比视口高一屏，页面被滚下去、底部露出大片空白。
改为在 `[conversationId]/page.tsx` 建 `ChatSessionProvider`（key 跟会话代次），store 归属唯一，
会话页与子树统一用 `useChatSessionStore()`。typecheck / 180 用例 / check:ui 全绿；SSR 直出已无错误标记。

**修"切右栏子 agent tab 整屏滚动"**：`react-resizable-panels@4` 的 Group 写死内联 `height: 100%`，
而会话页是「页头 + 分栏组」竖排 flex，`100%` 按整个 section 算 → 溢出约一个页头（~57px）。溢出被
`overflow-hidden` 裁掉后最外层仍留下可程序滚动的余量（hidden 不挡 focus / scrollIntoView），焦点一动整页被顶上移。
改法：Group 传 `style={{ height: 'auto' }}` 交给 `flex-1` 分配剩余空间；独立布局根 `overflow-hidden` → `overflow-clip`
（不建立滚动容器）。typecheck / 180 用例 / check:ui 全绿。

**修"切子 agent tab 后整页可滚动"（contain: paint）**：实测切 tab 后
`document.scrollingElement.scrollHeight` 900 → 8149 —— 子助手过程（8030px）虽被面板内部滚动区
与 `overflow: hidden` 裁住，其可滚动溢出仍计入根滚动区。逐层试验：`overflow: clip` 无效，
面板内层加 `contain: paint` 后回到 900（面板内滚动不受影响）。已把两栏 `ResizablePanel` 的 style
补上 `contain: 'paint'`；`pnpm typecheck` / 180 用例 / `check:ui` 全绿（无头浏览器仅用于这次取证，已清理）。

**修"答案还在提交中，后端已经输出；答完后处理中状态消失"**：续跑（`/agent/chat/resume`）不走 `useChat`
的 `sendMessage`，两个问题同源 —— ①`answerQuestions` 把整个续跑流 `await` 完才返回，卡片一直显示
「提交中…」；②续跑期间 `status` 停在 `ready`，「AI 正在处理」与停止入口都消失。改法：请求一被接受
就把该挂起块标成已回答（`resume-answer.ts` 的 `markSuspendedAnswered`，dock 立刻收起、时间线留只读记录）、
置 `resuming` 并让 `streaming` 覆盖它，续跑流交给后台消费、函数立刻返回，出错只提示不回滚。
另修同步游标：`sync` 原先只从 `applied - 1` 重放（消息中间的改写永远同步不到），改为按 parts 引用快照
找"第一个变了的 part"再重放。typecheck / 187 用例 / check:ui 全绿。
