## 内部调用收口：runtime 对话执行入 SDK、workspace-service 回调 main 走 SDK

排查发现 main 仍裸 fetch 调执行面（8 处，违反 D9「app 间调用统一走 internal-sdk」），且 workspace-service 反向调 main 的凭据两条接口也是手写 fetch。收口：

- `@repo/internal-sdk`：`AgentRuntimeClient` 补 `chat` / `stopRun` / `snapshotCurrentRun` / `snapshotRun`（204 与空 body 归一成 `null`：上游 Issue 3 的既有语义）与 `openStream`（只建连不解析帧，204/空体回 `body: null`）；`http.ts` 抽出 `performRequest` / `parseJson`，新增 `requestJsonOptional` 与流式入口，`InvokeOptions.headers` 支持身份头；
- 新增 `MainInternalClient`（workspace-service → main 的 `credentials/resolve`、`credentials/import`），workspace-service 两个手写 fetch 改走它，失败文案仍透传控制面中文原因；
- main：新增 `AgentRuntimeGateway`（唯一出口，统一拼身份头 `x-user-id`/`x-admin-id`/`x-request-id` 与超时）+ `agent-runtime.env.ts`（地址/令牌唯一读取处）+ `stream-drain.ts`；两个 controller 去掉裸 fetch 与重复的 headers/drain/runtime；`/agent/chat` 改为 main 侧共享 schema 校验。顺带修掉 control 侧漏转 `x-request-id`。
