- `@repo/internal-sdk`：`AgentRuntimeClient` 补 `chat` / `stopRun` / `snapshotCurrentRun` / `snapshotRun`（204 与空 body 归一成 `null`：上游 Issue 3 的既有语义）与 `openStream`（只建连不解析帧，204/空体回 `body: null`）；`http.ts` 抽出 `performRequest` / `parseJson`，新增 `requestJsonOptional` 与流式入口，`InvokeOptions.headers` 支持身份头；

## 修复：容器里凭据调用连不上（MAIN_URL 缺失 + compose 令牌不一致）

compose 与 k8s 的 workspace-service 都没配 `MAIN_URL`，schema 有默认值所以启动不报错，容器里回落到 `127.0.0.1:9989`，直到第一次凭据解析/入库才 `fetch failed`。另外 compose 把 `WORKSPACE_INTERNAL_TOKEN` 覆盖成 `dev-workspace-token`，与公共锚点的 `local-dev-workspace-token` 不一致 → main / common-capability 调工作区会全部 401（本地 `.env` 两边同值，所以只在 compose 文件里暴露）。

修：compose 补 `MAIN_URL: http://main:9989` 并去掉令牌覆盖；k8s 14 号 ConfigMap 补 `MAIN_URL: http://billy-main.billy.svc.cluster.local:80`；workspace-service 启动期自检（生产 / 集群里没配 `MAIN_URL` 拒绝启动，本地开发放行，显式写 127.0.0.1 也放行）；`docs/guide/env.md` 同步。验证：workspace 169 测试（新增 5 条自检用例）、typecheck 17/17、test 19/19、verify 全绿、`docker compose config` 通过。
