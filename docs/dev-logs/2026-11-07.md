# 2026-11-07

**全量依赖升级到最新（registry 2026-11-07）**：Node 26.13.0 + pnpm 12.18.0；Docker 基础镜像改
`node:26.13.0-alpine`（Node 26 不再内置 corepack，改为 `npm install -g pnpm@12.18.0`），
server / web 的 `FROM` 同步为 `node26-pnpm12:1.0`。关键落点：Next 16.4.5、React 19.3.1、
NestJS 12.3.3、TypeORM 1.1.2、Tailwind 4.3.5、AI SDK 7.0.164、Mastra 1.82.0 / memory 1.41.0、
TanStack Table 9.3.1 / Query 5.107.1、Vitest 5.1.0、jsdom 31、Motion 14、katex 0.19.1。
`crypto-js` 已停止维护，HMAC 实现换 `@noble/hashes`；`prom-client`（无使用）与空壳
`@types/bcryptjs` 删除。

**踩到的坑**：

① TanStack Table 9 重写 API：`useReactTable`/`getCoreRowModel` 换成 `useTable` +
`features: { ...coreFeatures, columnVisibilityFeature }`（`getVisibleCells` 属 column-visibility）；
`DataTableColumnDef` 改为 `ColumnDef<typeof tableFeatures, T, any>`。

② ioredis 6 与 TypeORM 1.1.2 的 peer `^5` 冲突，pnpm 为 kits 装了第二份 typeorm，
`FindOperator` 私有成员分属两个声明 → server 全部 `In()`/`IsNull()` 报 TS2322。**ioredis 留在
5.11.1**（6 的收益低、代价是类型系统分裂）；等 TypeORM 放开 peer 再升。

③ jsdom 31 的 `parse5-parser-stream@8.1.0` 调用了 parse5 8.1 才有的
`tokenizer.flushCharacters`，pnpm 解析到 8.0.1 时 jsdom 初始化直接 TypeError；
在 `pnpm-workspace.yaml` 加 `parse5@>=8.0.0 <9.0.0-0: 8.1.0` override。

④ AI SDK 7 的 usage 顶层字段移到 `outputTokenDetails.reasoningTokens` /
`inputTokenDetails.cacheReadTokens`；`tool.description` 可以是函数，展示层要先判类型。

⑤ Base UI 1.9 的 `HoverCardTrigger` render 函数把 ref 类型放宽成 anchor/button 联合，
`context.tsx` 改成 `render={<Button .../>}` 元素形式。

验证：typecheck / 7 包 test / check:ui / check:inject / check:mastra / check:scaffold / 全量 build 全绿；
server 起停冒烟 `/healthz`、`/readyz`（db/redis ok）通过。

**补丁补齐与 unified 双版本**：首轮 `pnpm up --latest` 受 minimumReleaseAge / 缓存影响，有 18 个包
只差一个 patch/minor（NestJS 12.3.3→12.4.0、Tailwind 4.3.4→4.3.5、aws-sdk 3.1163→3.1164、
lucide 1.69→1.70、motion 14.9.1→14.10.1、zustand 5.0.16→5.1.0、tsdown 0.23.5→0.23.7、
ai 7.0.163→7.0.164 等），改用显式版本 `pnpm up -r <pkg>@<ver>` 补齐。补齐后 lockfile 重解析，
`@streamdown/cjk` 的 `CjkPlugin.remarkPlugins` 类型仍指向 unified 11.0.0、streamdown 用 11.0.5，
`PluginConfig` 赋值报 TS2322；加 override `unified@>=11.0.0 <12.0.0-0: 11.0.5` 并清空
node_modules 重装才真正生效（旧符号链接不会被 `pnpm install --force` 重建；admin 还有
`tsconfig.tsbuildinfo` 缓存旧路径，要一并删除）。pnpm 12 的 `permissions` 批准了
`@tanstack/react-table` / `tsdown` 的 agent skills，外部技能装进 `.agents/skills/` 并由该目录的
`.gitignore` 忽略。复验：typecheck --force / 7 包 test / 全量 build 全绿。

**修告警规则页 React 重复 key 刷屏**：`/main/monitor/rules` 两张列（级别、阈值）都用
`accessorKey: 'config'`，TanStack 生成的列 id 相同 → header 与每行 cell 的 key
（`${row.id}_${column.id}`）重复，控制台刷 20+ 条 "same key `config`" 告警。
改为 `id: 'level' | 'threshold'` + `accessorFn` 取值（cell 仍读 `row.original.config`）。
复验：admin `tsc --noEmit` 通过；页面控制台告警交用户刷新确认。
