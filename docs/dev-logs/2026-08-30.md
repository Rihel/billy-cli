## 14:45 优化 api-client 的 buildUrl

- 做了：packages/api-client 的 buildUrl 改为基于标准 URL 构造（删除 normalizePath 与手写字符串拼接）；新增 appendSearchParams / serializeParam：过滤 undefined/null、数组展开为重复键（ids=1&ids=2）、嵌套对象 JSON 编码；path 为完整 URL / 协议相对 URL 时直接使用；baseUrl 尾斜杠不再产生双斜杠、path 自带查询串时与 params 以 & 合并。

## 15:00 buildUrl 支持 baseUrl 带 path

- 做了：buildUrl 改用 resolveUrl —— 完整 URL 直接使用；相对路径以「URL 对象 + pathname 拼接」落在 baseUrl 的 path 之后（如 baseUrl=https://api.test/api/v1 + /users → /api/v1/users），path 自带的查询串/hash 用 URL 构造拆出后走 search/hash 设置，避免 pathname 转义 `?`；补前导斜杠后根相对解析，消除对 baseUrl 尾斜杠的依赖。
- 坑点：`new URL('users', 'https://api.test/api/v1')` 相对解析会把无尾斜杠 base 的最后一段当文件折叠成 /api/users；pathname 直接赋值会把 `?` 编码成 %3F。
- 解决：vitest 50 通过（新增 3 条 baseUrl 带 path 用例）、tsc 零错误、构建成功。
