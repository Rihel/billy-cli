## 22:35 从 git 历史清除入库的私钥（本地完成，远端待 force-push）

  再 `git filter-branch --index-filter 'git rm --cached --ignore-unmatch <两个文件>' --prune-empty -- main`
  （本地无 git-filter-repo，filter-branch 对本仓 170 余提交足够），
  然后删 `.git/refs/original`、清全部 reflog、`git gc --prune=now`。
- 验证（关键判据）：**重写前后 `HEAD^{tree}` 完全一致（`7c36c9f7…`）** —— 只改历史、没碰内容；
  `git log main -- <两个文件>` 为空；`git rev-list --objects main | grep localhost` 为空；
  提交数 170 → 172（正是本轮新增的 2 个，说明 `--prune-empty` 没有误删任何提交）。
- **重要现状**：本地的 `refs/remotes/origin/main` 在 `ad04f0f`，即**远端已经包含含密钥的历史**

- **未做（不越权）**：向远端推送重写结果需要 force-push，按本仓「只提交不推送」的约定留给你执行：

## 00:08 Kafka 不阻塞启动 + 请求路径快失败（可用性加固）

- 需求：Kafka 启动不要阻塞 server 启动，尽快让服务可用。
- **先调查（关键）**：**启动本来就沒被阻塞** —— 连接是惰性的（`new Kafka()` 不发网络请求），
  消费者扫描 `onApplicationBootstrap` 是同步返回 + 后台浮动 Promise。实测（各 3 轮）：
  不配 Kafka 首次可服务 726 / 729 / 724ms，`KAFKA_BROKERS` 指向黑洞地址 734 / 735 / 729ms，
  差 5~9ms 属 DI 噪声。
- **真正的可用性风险在请求路径**：`getProducer()` 会 `await connect()`，而 kafkajs 默认
  `connectionTimeout: 1000` + `retry.retries: 5`，外层 `p-retry` 又重试 3 次 ——
  实测 broker 不可达时**一次 `send()` 要等 37.2 秒**（单次 connect 就 9.99s），
  足以把 HTTP 请求拖成超时。
- 做了（`packages/kits/src/kafka/`）：
  ① `KafkaConfig` 新增快失败配置 `connectionTimeoutMs`（3s）/ `requestTimeoutMs`（15s）/
  `retryCount`（2）/ `retryInitialDelayMs`（300）/ `unavailableCooldownMs`（5s），
  全部 `z.coerce.number()` 以便走 env；`createKafkaConnection` 透传给 kafkajs；
  ② `KafkaService` 增加**可用性冷却**：建连失败 → 标记不可用 + 记下原因；
  冷却期内 `send` / 建连**立即**抛 `KafkaUnavailableError`（带 `retryAfterMs`）；
  成功即恢复；`getAvailability()` 供健康检查/降级判断；关闭时复位。
  冷却判断刻意放在 `p-retry` **之外**（放里面会被 `minTimeout` 拖出 200ms）；
  ③ `send` 外层重试从 3 次降到 1 次（有界）；④ 消费者启动日志补「恢复后需重启」提示。
- 量化对照（broker 指向 `127.0.0.1:1`）：旧默认一次 `send` 失败 **37.2s** → 新默认 **1.02s**，
  冷却期内再次 `send` **0ms** 抛 `KafkaUnavailableError`（`retryAfterMs≈4798`）。
- 新增 `packages/kits/test/kafka-availability.test.ts`（5 项，kits 126）：锁住
  「`onApplicationBootstrap` 同步返回且不等建连（装饰器元数据用 `Reflect.defineMetadata` 写，
  因为 **kits 的 vitest 解析不了装饰器** —— 已记进 write-tests skill）」、
  「构造 kafkajs 客户端不发网络请求」、「send 有界失败 + 冷却期立即失败」、配置默认值。
- 文档/skill：kafka skill 新增「可用性规则」小节与配置表（含实测数字），
  guide 补 env 表、生产者降级示例、失败语义表；`apps/server/.env.example` 与
