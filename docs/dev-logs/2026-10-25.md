# 2026-10-25 开发记录

**问答卡改逐题交互**：`ask-user-questions` 的问题卡改成 stepper —— 一次只显示一道题，
答完当前题才能「下一题」，可用「上一题 / 下一题」来回切换，最后一题「提交回答」一次交整组
答案（resume 入参是整组 `answers`）。续跑出参改为结构化 `{ text, answers }`（`toModelOutput`
只把 `text` 交给模型），历史据此把 `tool-result` 的答案配回挂起行，按原 `seq` 留在时间线当
只读问答记录；老数据里的整段文本也按题号切回来。实时续跑时用提交前的 `suspendPayload`
补回问题原文，避免 AI SDK 同 id 覆盖后只剩「已回答」。

**子 agent 的问答边界**：问题卡只挂主 agent；子 agent 工具面来自注册机，本来就拿不到
`ask-user-questions`，本次补了能力尾巴的一句话与注册机的断言（`childToolbox()` 不含它）。

**子 agent 并行（单轮最多同时 3 个）**：主 agent 的 stream / generate / 续跑统一传
`toolCallConcurrency: { strategy: 'called' }` —— 默认 `available` 会因为工具集里有
`ask-user-questions` 把整步压成串行。并发上限由 `AgentRunner` 的 `KeyedSemaphore` 按父 run
兜住（`SUB_AGENT_MAX_CONCURRENT = 3`）：槽位随子 run 生命周期持有，第 4 个排队；配额
`count → create` 走同一父 run 的串行队列，避免并行判定一起越过 `maxPerRun`。补了闸门单测与
e2e（一步派 4 个 → 4 个都跑完、区间重叠峰值正好 3）。

**工具条宽度默认铺满**：`PageToolbar` 根节点补 `w-full`，不再依赖父容器是 flex-col 才被拉满；
AI 会话的**助手消息内容**从 ai-elements 默认的 `w-fit` 改为 `w-full` —— 工具调用条 / 子助手卡 /
事件条 / 问答卡都铺满会话宽度，不再因为内容短而缩成半截；用户气泡仍保持 `w-fit`（贴内容收紧）。

**富内容围栏**：正文围栏按语言分流到自定义渲染器（Streamdown `plugins.renderers`）：
```mermaid` 已有；`xflow`（JSON → React Flow，只给"谁连谁"，分层排版由前端算）、`html`
与 `gsap`（沙箱 iframe 直出页面 / 动画）。沙箱 `sandbox="allow-scripts"` 不带 same-origin，
文档内 CSP `default-src 'none'`：实测框内 `fetch('https://example.com')` 被拦（TypeError: Failed to fetch），
gsap 3.15.0 在框内可用、tween 生效。围栏没闭合只出占位（`isAnimating` 由 `message-row` 传
`streaming && part.state === 'streaming'`），避免每个 token 重建 iframe / 重排图。

**公式样式**：块级 `$$…$$` 之前只出了 KaTeX 结构、没引 `katex.min.css`，字形是错位的；
现在 `message.tsx` 引样式，katex 固定 0.16.x（与 rehype-katex 生成的结构同版本）。
行内 `$…$` 保持关闭（会和 `$5 到 $10` 这类金额撞）。

**gsap 资源**：`apps/admin/public/vendor/gsap.min.js` 随仓库提交，用
`pnpm -F @app/admin sync:vendor` 从 node_modules 同步；沙箱连不出去，所以只能由父页面同源取回后内联。
注入位置在模型内容**之前**（`<head>`）——放在后面时模型的内联脚本先执行，实测直接 `gsap is not defined`。

**字符画与行号**：真实会话里问"画个朝廷组织架构图"，模型用 ```` ```text ```` 拼带框线的树，
中文等宽两格、框线一格，靠空格对齐必然错位；代码块还默认带行号，把内容挤得更窄。两处都改：
`MessageResponse` 传 `lineNumbers={false}`（上游默认 `true`），提示词的「富内容围栏」一节
明确**禁止 ASCII / 字符画拼图**，结构图一律走 `xflow` / `mermaid`，纯文本只能缩进列表。

**流程图全屏**：`xflow` 围栏右上加「全屏」，开 92vh × 96vw 弹窗，里面是同一份数据、同一套排版的
另一个画布实例，切到**撑满 + 可拖动画布 + 缩放控件**（`XflowCanvas` 的 `fill` / `interactive`）。
会话里那张保持定高只读（拖动会和页面滚动抢手势），全屏里才放开拖动。用弹窗而不是浏览器

**流程图改用 dagre 排版 + 沙箱全屏**：`xflow` 的排版从自己写的「最长路径分层」换成
`@dagrejs/dagre`（React Flow 官方布局示例同款）—— 会做层内排序与坐标优化，菱形分叉 / 交叉边 /
回边都排得开。dagre 只有百来 KB 但也不该进首屏包，所以连画布一起放在 `xflow-canvas` 里按需加载，
`xflow-layout.ts` 是纯函数（可单测）；容器高度改由画布回报内容尺寸，不再先拍一个再跳。
`html` / `gsap` 也补了全屏：同一套 92vh 弹窗，里面是另一个 iframe、沙箱参数一字不改（脚本从头再跑）。
实测（无头 Chrome）：7 节点 8 连线的菱形+回边图，0 重叠、层间距正常。

**JSON 查看器 + json 围栏**：新增 `@repo/ui` 的 `JsonView`（`components/json-view.tsx`，走汇总导出）——

原文/树切换、复制；解析失败给原因并保留原文。上限刻意留着：原文 > 200KB 或条目 > 2000 退回原文并说明，

**开发 agent 的记忆目录**：新增 `.agents/memory/`——给「开发这个仓库的 AI」用的结论型记忆，
与 skill（该怎么做）、design（为什么这么设计）、dev-logs（哪天做了什么）分工，只收「查过才知道的」
坑 / 地图 / 实测数字 / 定过的取舍。入口是 `memory/README.md` 的索引（30 条以内，每条一句话），
命中主题再读对应卡片；卡片必带「依据」（文件:行 / 提交 / 实测日期）与「失效信号」，条件变了改旧卡
不并排新增。首批四张卡来自本次调查：压缩链路现状、AI 运行期文件地图、会话记录查法、token 成本构成。
接入点：`AGENTS.md` 加记忆指针、`billy-dev-foundation` 加「先查记忆」一节与完成清单一条。

**成本调查结论**：12 个会话实测，skill 注入只占工具输出 1%–3%；`bash` 输出占 84%，
其中用 shell 读文件 / 搜索又占 bash 的 84%。成本主项是「调用次数 × 累积上下文」——
最大会话 982 步、122 万字符（≈61 万 tokens）、全程未压缩。另查出 `ai_models` 里
`deepseek-flash` 有 sync（窗口 1048576）与 manual（窗口为空）两行，压缩从未产出摘要（`timelines` 0 条 summary）。

**记忆加查证优先级**：级别定义与判据放进 `AGENTS.md`（跨任务的行为规则不藏在被检索的目录里），
卡片顶部只标「必核 / 抽核 / 免核」：
行号、字段值、库里记录、常量、开关属必核（用前跑卡里的核对命令），文件路径与链路归属属抽核
（相关目录近期改过才核），机制性结论与带口径的历史实测属免核。索引表加「查证」列，一眼看出要不要核；
`ai-context-compression` 补了三条核对命令（grep 判定点、数 summary、查模型窗口）。
标了必核却不写核对命令视为不合格——不让人现猜。

**查证顺序**：写进 `AGENTS.md`——按成本从低到高取证：记忆索引 → codegraph（符号 / 调用关系 / 影响面）
→ 开发日志（哪天、因为什么变成现在这样）→ 代码（最终事实来源，也最贵）。前三级与代码冲突以代码为准，
并回头修正记忆；任何一级查出的可复用结论收尾沉进记忆，下次直接从第 1 级命中。
与 `code-conventions.md` 第 10 条的「实现查找顺序」（包 → 包内 → 已声明依赖）是两件事：
前者管「从哪取证」，后者管「代码里找现成实现」，已在两处互相指明。
