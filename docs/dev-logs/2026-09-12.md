## 20:10 装配层重构：KitsModule 拆成 per-infra module，配置即模块 bean

- 背景：`KitsModule.forRoot(config)` 把全部基建聚成一个中央模块、配置聚成一个大对象，
  与「一个基础设施一个 NestJS module」的惯例不符，也让按需装配 / 单测 / 复用变难。
- 做了：① 删除 `KitsModule` / `KitsConfig` / `kits.module.ts`，改为 15 个 `@Global()` 模块
  （IdGeneration / Scheduler / Logger / Telemetry / Db / Redis / Queue / StreamHub / Jwt / Session /
  Password / ObjectStorage / Lark / Notification / Kafka），每个用 `XxxModule.forRoot(options)`
  显式接收自己的配置分片，模块内 `Schema.parse(options)` 校验 + 补默认值，**配置对象即该模块的
  注入 bean**（DbConfig / RedisConfig / JwtConfig / AuthConfig / StorageConfig / NotifyConfig /
  LarkConfig / KafkaConfig 名称不变）；② 无配置模块（Queue / StreamHub / Session）复用上游模块的
  配置 bean（RedisConfig / JwtConfig / IdGeneration）；③ `LarkNotifyClient` 的 `LarkClient` 改
  `@Optional()` 注入，未装配 `LarkModule` 时该通道自动降级为「未配置」，因此 `NotificationModule`
  恒定装配四个客户端，不再需要「lark 存在才装配 LarkNotifyClient」的条件；④ `apps/server/src/app.module.ts`
  与 CLI `service` 模板改为逐个 `forRoot` + 展开语法做可选分片（Lark / Kafka）；⑤ 顺带修两处既有类型
  缺陷：`createDb()` 签名收紧为 `Omit<PostgresDataSourceOptions, 'type'>`（type 固定 postgres），
  `pagination.ts` 泛型补 `extends ObjectLiteral`；⑥ 文档与 skill 全量同步（README /
  billy-dev-foundation / 各功能 skill / design 文档）。
- 验证：文档侧 grep 校验无 `KitsModule` / `KitsConfig` 残留（历史 dev-logs 与已标注废弃的设计文档除外）；
