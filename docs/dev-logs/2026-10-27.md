# 2026-10-27 开发记录

**会话页选模型后"回到默认"**：用户报「选了非默认模型，一发消息就切回默认」。CDP 实测（Next 16.3.5）：
新会话首轮发出后地址 `new → 真实 id` 的 `router.replace` **会重挂载整棵对话区**（textarea 元素被换掉、
`loading` 又变回 true）——与 §4.9.4「同一动态路由换参数不会重挂载」的旧结论相反；`runs.request_snapshot.model`
显示那一轮用的仍是选中的模型，所以只是**界面 state 被重置**。修法：选中的模型按会话存
`localStorage`（`ai-chat-model:<会话 id>`，`new` 段是"下个新会话的待用选择"，首轮落真实 id 时搬家），
挂载后 effect 读回；存的选择已不在可选清单（模型被删 / 停用）时归零交回默认，避免每轮吃 3402。

**模型选择弹窗太窄**：`DialogContent` 默认 `sm:max-w-sm`（384px）装不下"名字 + 模态徽标 +
`provider/model` + 窗口"，实测名字列只剩 7.9px（界面看起来就是模型名消失）；行内还多画了一个勾
（`CommandItem` 自带一个 + 我们自己一个）。改为弹窗 `sm:max-w-2xl`（672px，名字列 326px）、
当前项改用 `data-checked` 驱动自带勾、`provider/model` 可缩可截断、窗口列 `shrink-0 tabular-nums`。

**开发流程加三条收尾规矩**（写进 `billy-dev-foundation/references/workflow.md` 的「验证与收尾清理」，

**选了模型输入框整块"变暗"**：用户报「选 V4-Pro 后输入框变暗」。根因在共享 `InputGroup` 的
`has-disabled:`（= `:has(:disabled)`）—— `PromptInputAttachmentButton` 在"当前模型不收附件"时是
禁用态，于是**整张输入卡连同模型选择、占位符、发送按钮、用量统计一起被降到 50% 透明度**；
实测截图里 muted 文字从 #6f7378 变成 ≈#a0a2a4、发送按钮从 #2b2d31 变成 ≈#7d7f81，正是 60% 白叠加。
改为只认组自己的输入控件：`has-[[data-slot=input-group-control]:disabled]:opacity-50`（深浅色各一处），
编译产物已核对为 `:has([data-slot="input-group-control"]:disabled)`。输入框真被禁用时仍会整组变淡。

**技能加载走 Mastra 的机制**：`SkillLoader` 只做发现 / 校验 / 授权（返回技能目录**绝对路径**），
内容交给 `Agent({ skills: [路径] })` → `LocalSkillSource`/`WorkspaceSkills`：清单进提示词、
正文与 `references/` 由 `skill` / `skill_read` 按需读（不再 `createSkill` 全读进内存）。
目录 = 打包的 `core/skills/catalog/`（坏技能启动即失败）+ `AGENT_SKILLS_DIRS`（默认 `~/.agents/skills`，
坏一个只跳过并记错误日志，重名前面赢）。`skills: ['*']` 在装配期展开成真实技能名（`/agent/list`、
`request_snapshot.skillKeys` 里都是具体名字）。实测：`~/.agents/skills` 24 个装进 23 个
（`xilo-opus-video` description 超 1024 被跳过）；一问"你能用哪些技能"答出 ant-design / impeccable 等；
代价是每轮多约 11k token（该轮 input 15690 vs 自估 4004，自估不含 Mastra 后注入的清单）。
