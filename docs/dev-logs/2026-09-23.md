# 2026-09-23

## 23:40 AI 能力全链路落地：会话落库 → 流式 → 恢复 → 动态子 agent → 前端两页

- 做了什么（按落地顺序）：
  1. **数据模型**：`conversations` / `runs` / `timelines` 三张表（TypeORM 实体 + 迁移）。`runs` 一行 = 一次执行，
     `timelines` 一行 = 一个 part（`seq` 是渲染顺序的权威）；**全部无物理外键**；`runs` / `timelines`
     永不删除，只有会话能软删（软删前先结束在跑的运行）。
  2. **存储适配层**：自实现 `MastraCompositeStore` 子类，**只实现 workflows 域 9 个方法**（记忆本轮不做），
     于是 durable agent 的快照落在我们自己的表里，不引 `@mastra/pg`、不自动建表。
  3. **运行时**：上下文组装（70% 触发 → 裁剪到 50% → 压缩到 40%，窗口来自 `tokenlens`，最近 3 轮不裁）、
     步骤与工具事件落时间线、终止收尾（终态 + 消耗 + 统计 + 会话累计 + 标题）。
  4. **流式**：`POST /agent/chat/stream`（AI SDK v6 UI Message Stream）+ `GET /agent/run/:runId/stream?offset=N`
     （Redis 补发 + 实时续接，204 语义）+ `POST /agent/run/stop`（本进程 abort / 跨副本广播）。
     `[DONE]` **在收尾落库之后**才发，客户端见到它就代表终态已写库。
  5. **恢复**：boot 取 Redis 租约 → `recoverAllDurableAgents()`；看门狗按心跳 + 总时长判超时
     （条件 UPDATE 抢占，多副本天然幂等）；恢复不了标 `interrupted`。
  6. **core bean + 动态子 agent**（本轮用户四点修正）：`AgentCore.asTools()` 交出跨业务的运行时能力
     （`PlannerCore` → `write-plan`；`SubAgentCore` → `run-sub-agent`）；子 agent 由主 agent
     **调用工具在运行期创建**（提示词由主 agent 现写、工具面 = 全部 − 委派类）、明细全量入库
     （独立 run + 完整时间线 + 动态提示词落 `request_snapshot`）、同一 `(parent_run_id, tool_call_id)`
     幂等复用、消耗汇总进父 run（轮数只数根 run）。
  7. **契约 + SDK**：`@repo/shared` 的 agent 契约（会话 / 运行 / 时间线 / run 详情等）+ `@repo/sdk`
     的 `agent` 分组（含 `chatStreamUrl` / `resumeStreamUrl` / `authHeaders` 三个给 AI SDK 用的旁路）。
  8. **前端**：ai-elements **48 个组件全量内置** `@repo/ui`（子路径、不进 barrel）；web `/ai/chat`
     （useChat + 全 part 渲染 + 子助手嵌套面板 + 历史从时间线重建）；admin `/main/ai/audit`
     （会话 → 运行树 → 时间线 + 输入快照，只读）。
- 坑点（都是真金白银踩出来的）：
  1. **`data-*` part 按 id 归并** → 子助手的流式增量绝不能用固定 id，否则只剩最后一块；
     状态用带 id 的 `data-sub-agent`、增量用不带 id 的 `data-sub-agent-delta`。
  2. **`writer` 才是动态子 agent 的出路**：`ToolExecutionContext` 里有
     `requestContext` / `agent.toolCallId` / `writer` / `abortSignal` 四样，于是"运行期创建的子 agent"
     能把明细写进**父的同一条流**，并靠 toolCallId 做幂等 —— 这三点是动态子 agent 成立的前提。
  3. **装配成环**：core bean 若要 `ToolBuilder`（才能知道"能给子 agent 什么工具"），就会
     `ToolBuilder → core bean → ToolBuilder` 成环。解法是**编排层算好、经运行时信封倒灌进工具**。
  4. **部分唯一索引的条件 TypeORM 检测不到**：`uk_run_active_conversation` 必须加
     `parent_run_id IS NULL`（否则子 run 与父 run 同时 running 一跑就撞唯一键），迁移里手工补写。
  5. **看门狗判据必须与候选查询完全一致**：`markTimeout` 早先只判心跳，"心跳还在跳但总时长超限"
     的运行永远处置不掉（新写的测试当场抓出来）。
  6. **测试配置漏字段 = 子 agent 立刻超时**：`subAgentTimeoutMs` 为 `undefined` 时
     `setTimeout(..., undefined)` 会立刻触发；Runner 里加了兜底值，测试栈也给全了配置。
  7. **`@repo/ui` 子路径导入必须带扩展名**：`exports` 的通配映射 `./* → ./src/*` 不做扩展名补全，
     `@repo/ui/components/ai-elements/message` 解析不到，要写 `.../message.tsx`。
  8. **`pnpm-workspace.yaml` 的 `@types/react` override**：cmdk 等包会单独解析出一份 React 18 时代
     类型，导致同仓库两套 `ReactNode`（ai-elements 的 `{children}` 全报类型不兼容），从依赖解析层收口。
