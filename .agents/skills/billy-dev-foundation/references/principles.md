# 工程首要准则（billy-dev-foundation 引用文件）

> 本文件是 `billy-dev-foundation` skill 的组成部分，承载**整个工程的最高准则**。
> 权威精简版见仓库根 `AGENTS.md`；本文件展开每条准则在开发中的落地点。

## 八条首要准则（一切任务的总纲）

1. **实事求是** —— 一切从实际出发，设计建立在工程真实约束之上，不拍脑袋、不凭空想象。
   - 落地：先摸清工程现状（分层、既有包、依赖、能力），再谈方案；不脱离现状臆造结构。
2. **没有调查就没有发言权** —— 动手前先读代码、查现状，结论产生于调查之后。
   - 落地：写任何代码前先读相关原文件（`grep` + `read`），不凭印象；与
     `code-conventions.md` 第 10 条「实现查找顺序」一体。
3. **抓主要矛盾** —— 先识别核心难点 / 主要影响面，集中力量解决主要矛盾。
   - 落地：面对复杂需求先定位「最难、最影响面大」的一两个点（状态一致性？并发？
     数据流？），优先解决，反对平均用力。
4. **具体问题具体分析** —— 不搞一刀切。
   - 落地：简单需求直接做，中等出简短方案，复杂先出完整设计（见 `design.md` 难度分级）。
5. **集中优势兵力，各个歼灭** —— 一次聚焦一个目标，小步快走。
   - 落地：一个逻辑变更一个提交；不贪多求全、不铺大摊子（见 `git-workflow` 提交粒度）。
6. **实践—认识—再实践** —— 方案从实践中来，到实践检验修正。
   - 落地：借鉴成熟实践 / 既有模式出方案，落地后验证修正；实践是检验设计正确性的标准。
7. **独立自主，自力更生** —— 借鉴思想而非照抄，核心能力自己掌握。
   - 落地：借鉴成熟方案的思路而非搬代码；无先例可循时用第一性原理兜底，不迷信现成方案。
8. **战略上藐视，战术上重视** —— 方向看准有定力，细节认真对待。
   - 落地：整体方向正确就推进，同时对边界条件、异常、并发、扩展逐一想清楚
     （见 `design.md` 系统化思维的「边界条件」）。

## 与具体规范的层次关系

```
首要准则（本文件 / AGENTS.md）       —— 立场与方法，统摄一切
  ├─ design.md         —— 怎么想（难度评估、系统化思维、借鉴/第一性原理）
  ├─ placement.md      —— 放哪（能力归位）
  ├─ code-conventions.md —— 怎么写（不重复造轮子 + 硬性约定）
  └─ workflow.md       —— 什么顺序（标准流程）
```

任何具体规范与首要准则冲突时，**以首要准则为准**；具体规范是首要准则在不同环节的展开。
