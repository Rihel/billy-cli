# 开发会话的 token 成本构成

> **查证优先级：免核** —— 机制性结论（每步重发全历史）与带日期的实测数字，用前不必重量。
> 引用时把「2026-10-25、12 个会话、按文本长度折算」一起带上；要换新数字就按
> `dev-session-log.md` 的方法重跑，别凭感觉改。

## 结论

2026-10-25 对 12 个本地会话的实测（口径：按 `tool/result` 的文本长度归类求和）：

- **skill 注入只占工具输出的 1%–3%**，不是成本主项。常驻的 skill 目录含在 11.7K–20K 字符的系统提示里。
- `bash` 输出占 84%；其中「用 shell 读文件 / 搜索」（`grep`/`sed`/`cat`/`ls`/`python3`）又占 bash 的 84%。
- 最大的一个会话：982 步、1054 次工具调用、累积消息 122 万字符（≈61 万 tokens），全程没有触发压缩。
  `sleep` 空轮询 45 次、输出超 2K 字符的 `bash` 492 次、最长单次 49,931 字符（`grep -rn` 打进了 `node_modules`）。
- 成本近似：`N × 常驻开销(6–8k tokens) + M × N / 2`（N = 步数，M = 累积消息量）。
  样本里主导项是第二项，所以**调用次数比 skill 字数重要得多**。

## 据此得到的做法

- 调查隔离到子 agent：翻文件的碎调用不进主会话，只回结论
- 批量取证：一次调用里串联多个目标，别一个关键词一次往返
- 优先 `codegraph` 查结构，替代 `grep` 爬仓库
- 边界收紧：`grep --include` + `head`，读文件用 `read` 的 `offset`/`limit`，别整文件 `cat`
- 会话别拖太长：调用数过几百就交接摘要另开
