# 待办报告

把散落的待办数据整理成一份可以直接发给同事或上级的报告。

## 何时使用

用户的说法接近下面任意一种时启用本技能：

- "写个周报" / "汇总一下待办" / "给我一份报告" / "看看这周进展"
- "哪些任务拖着没动" / "有没有长期没更新的待办"
- 要求把待办整理成表格、邮件或汇报材料

## 取数口径（不要跳步）

1. 先调用你**当前可用的查询类工具**（能按列表 / 条数返回待办的那个），拿到**全量条数**与**取样明细**。
2. **区分两个数**：全量条数是一个数；取样明细只是本次拿到的部分。报告中必须写明取样条数，
   例如「共 37 条，其中最近更新的 20 条如下」——不要把取样当成全量结论。
3. 需要某一条的细节时，用你可用的查询工具按 id 再查一次，不要凭标题猜测内容。
4. **没有可用的查询工具时**：如实说明"现在取不到待办数据"，请用户到后台「待办管理」页面查看或导出；
   **绝不编造条数、标题或日期**。

## 统计维度

- **完成情况**：取样中已完成 / 未完成各多少条，给出完成率（注明是取样的口径）。
- **长期未更新**：更新时间距现在超过 7 天的未完成条目，单独列出并标注天数。
- **主题聚类**：标题里有共同关键词的（如"支付""文档"）合并成一组，便于看出工作重心。
- 数据为空时直接写"本期没有待办记录"，**不要给出推测数字**。

## 输出结构

按 `references/report-template.md` 的结构输出，四段：概览 / 明细 / 风险 / 建议。

- 概览只给关键数字，不超过两行；
- 明细用短列表，每条含标题与状态；
- 风险段只放真正需要人介入的（超期未更新、明显重复）；
- 建议段最多三条，且必须是基于上面数据能直接执行的（如"确认 X 是否已经废弃"）。

## 语气

平实、短句、不堆形容词；不使用"赋能""抓手"这类空词。
报告是给人做判断用的，不是给人看排比的。
